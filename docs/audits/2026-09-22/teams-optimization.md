# Teams 群聊抓取优化与验收

验证日期：2026-09-22。用户指定群聊：Roku Announced。实测使用用户提供的深链接进入已有登录状态，仅定位、滚动和读取，没有发送消息。

## 修复内容

- 会话链接提供 ID 时优先按完整 ID 定位，禁止同名标题兜底串群；同名候选不再任意选择第一条。
- 每轮提取核对群标题，抓取中切换到其他群会停止且不写入；开始前及各滚动阶段检查取消。
- 消息 ID 取自 `data-mid` / `data-message-id`，作者和时间从对应外层消息行读取；不使用重复的 `data-tid` 组件名称作为身份。
- 图片、表情与附件保留占位/可用描述和链接；群系统消息也纳入记录，不编造其缺失的作者或时间。
- 按一个稳定消息节点对应一条记录提取，避免嵌套头像、引用和系统消息被重复计数。
- 兼容旧 `message-body-数字` ID 与当前数字 ID，旧通用组件 ID 使用内容身份；消息编辑更新同一记录，不删除部分抓取中没看到的历史。
- 消息去重与重叠判断使用稳定 ID 或完整作者/时间/正文，不再使用 180/240 字前缀，也不再静默截断为最后 240 条。
- 优先滚动 `message-pane-list-viewport`，避免误滚聊天侧栏；直接滚动成功后不叠加滚轮，减少跳过虚拟列表区间的风险。
- 不等待 Teams 的长连接网络空闲，改为等待消息 DOM；完成后回到最新消息并检查底部。
- WebDriver 保存本次消息快照，不再保存包含其他群列表的整个页面 HTML；明确记录 `partial` 及本次滚动停止原因。
- 浏览器用户脚本同步采用同一提取器；Teams 单页应用地址停留在根页面时，通过唯一群名称匹配会话 ID，无法确认则跳过，不以根 URL 合并不同群。

## 验证范围

此次验证的是浏览器群聊消息采集和本地 HTTP 保存流程。使用已登录 Ego 浏览器执行项目相同的读取、滚动函数，未把登录态复制到应用独立的 Playwright 用户目录。因此，Electron 内首次登录与人工确认流程没有被此次实测覆盖；团队频道、Graph API 也未做真实账号验证。

虚拟列表只代表本轮观察到的范围，不能声称已抓取群的全部历史；滚动上限或增量重叠停止均保持“部分抓取”。图片只有占位及描述，没有下载或 OCR。真实内容写入独立临时资料库进行重复抓取验证，验证后删除；正式资料库保持不变。

## 真实入库回归发现的修复

首次真实重复入库断言发现：相同消息第二次保存仍返回 changed=true。首次正文来自调用方，后续正文来自合并渲染器，二者格式不同。现在 Teams 首次创建与后续更新都先规范化消息顺序并使用统一渲染器；HTTP 回归确认相同消息重复提交不改变 contentUpdatedAt，也不产生假的未读更新。身份依据同时改为可持久化的对象，避免字符串被元数据校验丢弃。
